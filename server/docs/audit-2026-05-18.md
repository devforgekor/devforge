## 2. HIGH — Fix This Week

### 2.1 Worker overlap: qwen_worker.py vs review_worker.py

Two workers independently extract facts from the same turns into different tables:

| | qwen_worker.py | review_worker.py |
|---|---|---|
| Timer | Every 15 min | :05, :35 (30 min) |
| Table | `observations` | `review_facts` |
| Model | qwen2.5-coder-7b (BROKEN) | qwen2.5-coder-14b → Phi-4 verify |
| Extraction type | Simple fact extraction | Self-contained facts + cross-validation |
| Dedup/validation | Text-based, within batch | Verbatim evidence verification by Phi-4 |
| DB schema | observation TEXT, category, source | evidence TEXT, fact_type, verdict, reason |

**Problem**: 
- qwen_worker Phase 3 and review_worker Phase 1 do the SAME thing (extract facts from turns) but produce different output in different tables
- qwen_worker's LLM path is broken (see 1.1), only Phase 1 (deterministic) works
- `observations` table has 104KB of data; `review_facts` has 72KB — partial duplication

**Recommendation**: 
- Since review_worker.py has proven superior results (97.9% valid, 2-phase verification), qwen_worker Phase 3 (observe) should be DISABLED
- qwen_worker Phase 1 (deterministic: ingest + link + backfill) remains valuable and should continue
- Phase 2 (classify) is still needed for LLM agent inference — fix model name
- Better: consolidate all LLM calls through review_worker.py pattern (http.client, single model dict)

### 2.2 SQL injection in _ensure_worklog()

**File**: `/opt/projects/server/scripts/qwen_worker.py:81-99`
**Risk**: `agent`, `model`, `date_str`, `title` values interpolated directly into SQL without `_esc_sql()`.
**Context**: `agent` comes from `normalize_agent(source)` (safe, limited to AGENT_MAP values). `model` comes from session parser output — could be arbitrary. `date_str` comes from `datetime.strftime` (safe). `title` is constructed from `date_str + " " + agent + " session"` (safe).
**Actual risk**: Low currently, but fragile. Any parser returning unexpected model strings could break queries.
**Fix**: Apply `_esc_sql()` to all interpolated values. Use same escape function as review_worker.py:165-167.

### 2.3 embed_turns.py uses different PG user

**Bug**: Uses `-U devforge` while ALL other scripts use `-U postgres`.
**Impact**: `devforge` user is not superuser. Currently works for basic operations but may fail on schema changes, extensions, or permission-restricted operations.
**Fix**: Change to `-U postgres` for consistency.

### 2.4 requests vs http.client dependency inconsistency
